## Подготовлено

- `src/cloudflare-worker.ts`: прежний webhook и очередь, обработка сообщений и расписание непосредственно в Cloudflare.
- `src/adapters/d1/store.ts`: постоянное хранилище D1, атомарная фиксация с проверкой версии, повтор транзакции при конкуренции.
- `wrangler.bot.jsonc`: отдельная D1 `friday-football-bot-v2`; прежняя D1 не затрагивается. `BOT_ACTIVE=false` — безопасный исходный режим.
- Проверка каждую минуту: дедупликация действия предотвращает повторное открытие/закрытие; отложенные сообщения повторяются после восстановления связи.
- За вызов обрабатывается одно служебное сообщение. Следующие обрабатываются входящими событиями либо таймером; при нескольких сообщениях возможна задержка до следующей минуты. Чтение истории команд внутри транзакции выполняется одним запросом, чтобы укладываться в Free-ограничения.
- Выгрузка YDB сохраняется только в игнорируемой `.artifacts/migration/`. Она содержит данные игроков: не публиковать и не коммитить.
- Статистика сверяется с исходными строками YDB; удалённая D1 перед активацией сравнивается побайтно на уровне каждой записи.

## Переключение

1. Сохранить текущую версию Worker для отката.
2. Остановить старый путь исполнения. Если сервис управления триггерами недоступен, обратимый вариант — снять тег `stable` с версии Yandex Function; старые таймеры и прежний Consumer вызывают именно этот тег. Проверить отсутствие тега. Сохранить ID версии для восстановления.
3. Получить свежую согласованную выгрузку YDB. Сверить с проверенным импортом; если отличается, подготовить импорт заново.
4. Применить схему к **новой пустой** D1; импортировать проверенную выгрузку. Не повторять INSERT поверх заполненной базы.
5. `node scripts/verify-d1-import.mjs` должен вернуть `verified=true` до появления новых рабочих записей.
6. Передать прежний `ADMIN_IDS` как секрет Cloudflare. `BOT_TOKEN` и `WEBHOOK_SECRET` уже есть у прежнего Worker; не менять их.
7. Развернуть `wrangler.bot.jsonc` с `--var BOT_ACTIVE:true`. Имя Worker, Telegram webhook и основная очередь остаются прежними, Consumer меняется на D1.
8. Проверить `/health`, фактическую доставку карточки и журнал CPU/ошибок. Проверять лимит 50 D1-запросов и 10 мс CPU на бесплатном тарифе, особенно итоговый рейтинг с накопленной историей.

Исходная база Яндекса остаётся резервной копией, старые таблицы Cloudflare остаются нетронутыми. Откат после новых записей D1 требует сначала сохранить эти записи; нельзя просто включить устаревшую YDB и потерять новые действия.

## Проверки

`npm test`, `npm run typecheck`, `npm run build`, `wrangler deploy --config wrangler.bot.jsonc --dry-run`.

355 тестов прошли; 14 проверок старой тестовой YDB пропущены из-за отсутствия отдельной тестовой базы. Проверки нового хранилища используют настоящий локальный движок D1. В том числе проверены одновременная регистрация, атомарность, дедупликация, доставка, отмена и лимит запросов при истории из 20 сборов. Исправлен и защищён тестом контекст вызова `fetch`, требуемый средой Workers.

Последняя рабочая проверка: регистрация открыта, message ID 1025, 10 мест заняты, ожидающих сообщений 0. После исправления сетевого вызова наблюдались успешные HTTP/Queue-вызовы без исключений. В выборке CPU HTTP 1–3 мс, Queue 8–20 мс; эти показатели не доказывают устойчивое соблюдение 10-мс лимита Free во всех сценариях.

**Стоимость аккаунта требует подтверждения.** Платная подписка при переносе не подключалась. Однако доступ к API подписок через существующий OAuth возвращает 403, а Cloudflare Dashboard требует входа пользователя. Проверить, что выбран Workers Free, и сопоставить пиковый CPU с его ограничениями после входа; до этого не утверждать, что фактический счёт аккаунта равен нулю. Исходная база и мониторинг Яндекса сохранены, поэтому их остаточные начисления также не объявлять прекращёнными целиком.

Скрипты: `scripts/export-ydb.mjs`, `scripts/prepare-d1-import.mjs`, `scripts/verify-d1-import.mjs`.

Экспорт получает IAM-токен через переменную процесса; секреты не входят в файлы выгрузки и журналы проверки. `scripts/deploy.ps1` относится к прежней установке Яндекса и после переключения не используется.
